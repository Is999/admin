# 内网初始化管理员接口

## 1. 适用场景

该接口用于项目首次上线、自举恢复或运维兜底场景，在系统里已经存在超级管理员账号的前提下，将该账号重置为首次登录前状态，避免因为历史密码未知或 MFA 状态残留导致后台无法登录。

该接口具备以下特点：

- 仅允许内网或回环地址访问。
- 免 JWT，但必须通过 Ops 令牌、HMAC、时间窗口和 Redis nonce 防重放校验。
- 同一超级管理员用户名重复调用时具备幂等语义。
- 仅允许重置既有超级管理员账号。
- 不允许新建账号。
- 不允许修改目标账号角色。

## 2. 接口地址

```http
POST /internal/auth/init-admin-bootstrap
```

### 请求示例

```http
POST /internal/auth/init-admin-bootstrap
Content-Type: application/json
X-Ops-Token: <ops.token>
X-Ops-Timestamp: <Unix 秒>
X-Ops-Nonce: <32 位小写十六进制随机数>
X-Ops-Body-SHA256: <请求体 SHA256>
X-Ops-Signature: <HMAC-SHA256>

{
  "username": "super999",
  "password": "Temp@1234",
  "realName": "超级管理员",
  "email": "super999@example.com",
  "phone": "13800000000",
  "description": "首次上线初始化账号"
}
```

## 3. 访问限制

- 该接口不是公网接口。
- 该路由只注册到 `internal_server` 独立监听器，公网监听器没有该路由。
- 请求来源必须命中私网 IP 或回环地址，并携带完整 Ops 签名；同一 nonce 只能使用一次。
- Redis 不可用时返回 HTTP 503，不会跳过防重放校验。
- 生产跨主机监听必须绑定明确私网 IP 并启用 mTLS；仅回环监听允许使用 HTTP。
- 不需要携带 `Authorization` 请求头。

### 3.1 请求头

| 字段 | 是否必须 | 说明 |
| --- | --- | --- |
| `X-Ops-Token` | 是 | 匹配 `ops.token`，同时作为 HMAC 密钥 |
| `X-Ops-Timestamp` | 是 | Unix 秒，允许前后 5 分钟偏差 |
| `X-Ops-Nonce` | 是 | 每次请求重新生成 16 字节随机数，使用 32 位小写十六进制编码 |
| `X-Ops-Body-SHA256` | 是 | 原始请求体 SHA256 小写十六进制摘要 |
| `X-Ops-Signature` | 是 | 对 `method\nrequestURI\ntimestamp\nnonce\nbodySHA256` 计算 HMAC-SHA256 |

### 3.2 回环监听 Curl 示例

以下示例对应本地 `internal_server` 回环端口；跨主机调用需改用 HTTPS，并追加客户端证书、私钥和 CA 参数。

```bash
OPS_TOKEN='<ops.token>'
BODY='{"username":"super999","password":"Temp@1234"}'
TIMESTAMP="$(date +%s)"
NONCE="$(openssl rand -hex 16)"
BODY_SHA256="$(printf '%s' "$BODY" | openssl dgst -sha256 -r | awk '{print $1}')"
SIGNATURE="$(printf '%s\n%s\n%s\n%s\n%s' \
  'POST' '/internal/auth/init-admin-bootstrap' "$TIMESTAMP" "$NONCE" "$BODY_SHA256" |
  openssl dgst -sha256 -hmac "$OPS_TOKEN" -r | awk '{print $1}')"

curl -sS -X POST 'http://127.0.0.1:8896/internal/auth/init-admin-bootstrap' \
  -H 'Content-Type: application/json' \
  -H "X-Ops-Token: $OPS_TOKEN" \
  -H "X-Ops-Timestamp: $TIMESTAMP" \
  -H "X-Ops-Nonce: $NONCE" \
  -H "X-Ops-Body-SHA256: $BODY_SHA256" \
  -H "X-Ops-Signature: $SIGNATURE" \
  --data-raw "$BODY"
```

返回成功后重点关注：

- `code = 1`
- `data.operation = "reset"`
- `data.needResetPassword = 1`
- `data.mfaStatus = 0`

## 4. 请求参数

```json
{
  "username": "super999",
  "password": "Temp@1234",
  "realName": "超级管理员",
  "email": "super999@example.com",
  "phone": "13800000000",
  "avatar": "",
  "description": "首次上线初始化账号"
}
```

字段说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `username` | 是 | 已存在的超级管理员登录用户名 |
| `password` | 是 | 首次登录临时密码，调用成功后需要由该账号自行修改 |
| `realName` | 否 | 真实姓名；显式传值时覆盖原值 |
| `email` | 否 | 邮箱；既有账号未传值时保留原值 |
| `phone` | 否 | 电话；既有账号未传值时保留原值 |
| `avatar` | 否 | 头像地址；既有账号未传值时保留原值 |
| `description` | 否 | 备注说明；既有账号未传值时保留原值 |

## 5. 处理规则

### 5.1 用户不存在

- 直接拒绝，不允许通过该接口创建管理员账号。

### 5.2 用户已存在但不是超级管理员

- 在当前写事务内通过 `admin_role_rel(user_id, role_id)` 与 `admin_role(id)` 索引点查确认启用的超级管理员角色，不读取角色缓存或副本。
- 校验不通过时直接拒绝，不允许通过该接口提升、变更或覆盖账号角色。

### 5.3 用户已存在且已经是超级管理员

- 重置该账号为首次登录前状态。
- 保留其既有超级管理员角色关系，不做任何角色调整。
- 清空既有 MFA 秘钥、MFA 登录完成标记和 MFA 二次票据缓存。
- 清空最近登录时间、登录 IP 与登录归属地。
- 登录后必须先修改密码，再按系统策略决定是否继续绑定 MFA。

### 5.4 数据库已提交但运行态清理失败

- 账号重置事务先提交，随后清理管理员登录态、权限缓存、MFA 登录标记和二次票据。
- 任一运行态清理失败时仍返回成功业务码和账号重置结果，`data.syncPending=true` 表示登录态、权限或 MFA 缓存正在自动补偿。
- 此时数据库重置不会回滚；恢复 Redis 后由后台补偿任务继续清理，不要重复提交账号重置请求。

## 6. 首次登录状态定义

接口执行成功后，目标账号会被统一收敛为以下状态：

- `needResetPassword = 1`
- `mfaStatus = 0`
- `mfaSecureKey = ""`
- `status = 1`
- `lastLoginTime = 零值`
- `lastLoginIP = ""`
- `lastLoginIpaddr = ""`

这保证该账号首次登录时：

1. 可以正常使用临时密码进入系统。
2. 会被要求先修改登录密码。
3. 修改密码后可继续绑定并启用 MFA。

## 7. 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "操作成功",
  "data": {
    "id": 1,
    "username": "super999",
    "roleID": 1,
    "needResetPassword": 1,
    "mfaStatus": 0,
    "status": 1,
    "operation": "reset"
  }
}
```

响应字段说明：

| 字段 | 说明 |
| --- | --- |
| `id` | 管理员 ID |
| `username` | 登录用户名 |
| `roleID` | 当前绑定的超级管理员角色 ID |
| `needResetPassword` | 是否必须修改登录密码 |
| `mfaStatus` | 当前 MFA 状态 |
| `status` | 当前账号状态 |
| `operation` | 本次操作类型；当前固定为 `reset` |

## 8. 使用建议

- 仅在首次上线、自举恢复或后台完全无法登录时使用。
- 执行成功后应立即使用返回账号登录，并完成密码修改。
- 若系统开启强制 MFA，建议在首次改密后立即完成 MFA 绑定。
- 公网监听器不会注册该接口；不要把独立内网监听端口暴露给公网。

## 9. 首次上线操作清单

推荐按以下顺序执行：

1. 确认服务已启动，且当前调用方位于内网或宿主机本机。
2. 确认目标账号已经存在且本身就是超级管理员。
3. 通过内网地址调用 `POST /internal/auth/init-admin-bootstrap` 重置该超级管理员账号。
4. 确认响应中的 `status=1`、`needResetPassword=1`、`mfaStatus=0`。
5. 使用返回的 `username` 和本次设置的临时密码登录后台。
6. 首次登录后立即修改密码。
7. 如果系统启用了强制 MFA，继续完成 MFA 绑定与启用。
8. 登录成功并确认菜单、权限、个人中心和 MFA 状态正常后，再交付业务或运维继续使用。

## 10. 常见用法

### 10.1 首次上线重置既有超级管理员

适用场景：

- 数据库里已经存在超级管理员账号。
- 需要把该账号恢复为首次登录状态。

### 10.2 已有超级管理员账号但无法正常登录

适用场景：

- 历史密码未知。
- 旧账号已残留不可用的 MFA 状态。
- 历史登录痕迹或 MFA 票据导致登录流程异常。

此时接口会把既有账号恢复为首次登录前状态，返回的 `operation` 固定为 `reset`。

## 11. 失败排查

- 返回未授权：
  检查来源 IP、Ops 令牌、时间戳、nonce、请求体摘要和 HMAC 签名；nonce 重复使用也会被拒绝。
- 返回 HTTP 503：
  检查 Redis 防重放链路是否可用。
- 返回参数错误：
  重点检查 `username` 是否为空、`password` 是否满足后台密码规则。
- 返回禁止访问：
  重点检查目标账号是否已经存在，且该账号当前是否本身拥有超级管理员角色。
- 返回数据库错误：
  重点检查后台管理库连接，以及角色关系查询链路是否正常。
- 调用成功但 `data.syncPending=true`：
  账号重置已经提交，但 Redis 登录态、权限缓存或 MFA 运行态尚未全部清理；后台会自动补偿，不要重复提交账号重置请求。
- 调用成功但登录后仍异常：
  检查是否命中了浏览器本地缓存或过期 token，必要时清理浏览器本地存储后重新登录。
