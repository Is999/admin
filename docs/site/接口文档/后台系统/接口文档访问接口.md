# 接口文档访问接口

接口文档页面必须先登录后台，再创建文档访问会话。会话接口只校验登录态、账号状态、IP、密码重置和 MFA，不绑定具体文档站权限；后台接口文档入口校验 `docs.index`，前台 API 文档入口校验 `docs.api_service.index`，具体 Markdown 资源按 `admin_doc_permission.site + path` 精确校验。

## 1. 创建文档访问会话

### 基本信息

- 请求方式：`POST`
- 请求路径：`/api/docs/session`
- RouteMeta：`ignore`，仅跳过业务权限表
- 权限：创建会话不要求文档入口权限；访问资源时入口匹配 `admin_permission.module`，正文匹配 `admin_doc_permission.site + path`
- 审计动作：无
- 鉴权：后台登录 Token

### 请求头

| 字段 | 类型 | 是否必须 | 说明 |
|------|------|----------|------|
| Authorization | string | 是 | `Bearer <token>` |

### 请求参数

无。

### 响应字段

| 字段 | 类型 | 是否必须 | 说明 |
|------|------|----------|------|
| expiresIn | int | 是 | 文档会话 cookie 最长有效秒数 |

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "成功",
  "data": {
    "expiresIn": 3600
  }
}
```

### Cookie 说明

- 名称：`admin_docs_token`
- Path：`/api/docs`
- HttpOnly：是
- SameSite：`Lax`
- Secure：HTTPS 请求或 `X-Forwarded-Proto=https` 时启用

## 2. 访问接口文档

创建会话后，浏览器可直接访问：

```text
GET /api/docs#/
GET /api/docs/api#/接口文档/前台系统/系统接口
```

文档静态资源支持以下路径：

- `GET /api/docs`
- `GET /api/docs/:path`
- `GET /api/docs/:path/:sub`
- `GET /api/docs/:path/:sub/:file`
- `GET /api/docs/:path/:sub/:group/:file`

访问这些资源时，所有运行模式都必须携带有效后台凭证。后端会优先读取 `Authorization` 请求头；没有请求头时读取文档会话 cookie，并按当前管理员权限过滤侧边栏、搜索索引和 Markdown 资源。

`/api/docs/api` 是前台 API 文档独立入口，页面壳由 Admin 提供，侧边栏和 Markdown 内容由 Admin 后端通过 `api_service.internal_base_url` 内网读取 API 服务的 `/internal/docs` 文档资源。API 服务不直接向浏览器提供文档站；内网资源只输出 `docs/site/_sidebar.md`、`docs/site/接口文档/**/*.md` 和 `docs/site/角色文档/**/*.md`，不输出 `route_security_manifest.json` 等非 Markdown 机器资产。

`/api/docs/vendor/` 是两个文档站共用的 docsify 静态依赖，只校验后台登录安全态，不绑定任一文档入口权限；文档首页、导航和 Markdown 正文仍分别执行入口与资源权限校验。

### 权限存储与匹配

- 文档入口是正常路由权限，存放在 `admin_permission`；单篇 Markdown 正文存放在 `admin_doc_permission`，稳定资源键为 `site + path`。
- 角色的正常路由权限存放在 `admin_role_permission_rel`，文档权限存放在 `admin_role_doc_permission_rel`；用户绑定角色仍存放在 `admin_role_rel`。
- 访问时后端先校验对应文档站入口，再按用户启用角色精确匹配正文资源。文件夹仅用于界面分组，不产生继承授权；超级管理员角色拥有全部文档权限。
- 鉴权按管理员角色、角色路由权限、角色文档权限、角色状态和共享资源索引完成校验；同一请求复用已解析的启用角色。
- 缓存 miss 才从主库重建；管理员换角色只失效该管理员角色关系，角色授权变更只失效受影响角色关系，权限定义变更会失效权限树和共享索引，删除权限时还会失效受影响角色关系。缓存异常时拒绝访问。
- 角色保存正文权限时会自动补齐对应文档站入口路由及其菜单祖先，避免正文有权限但入口不可见。
- 侧边栏、顶部导航和搜索索引按同一套权限过滤；直接访问 Markdown 资源仍会再次校验，避免只隐藏菜单但直链可读。

### 文档入口权限

| 文档站 | 后端权限 module | uuid |
| --- | --- | --- |
| Admin 后台文档 | `docs.index` | `200029` |
| API 服务文档 | `docs.api_service.index` | `200068` |

单篇文档权限由 `internal/database/assets/admin_doc_permission.sql` 维护，`internal/routealias/docs.go` 的 `DocsResources` 与 Admin/API 两个仓库的实际 Markdown 文件列表有回归测试校验。新增正文必须同步追加 `site + path` 基线；未登记 Markdown 默认拒绝访问。
