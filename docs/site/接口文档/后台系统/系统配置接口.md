# 系统常量配置接口

`sys_config` 表归属 config 库，查询、新增、编辑和缓存回源均使用配置库连接，避免误写后台管理库。

新增、编辑或导入已经提交数据库但缓存刷新失败时，接口仍返回成功业务码并设置 `data.syncPending=true`；前端必须提示手动刷新，不能重复提交原写操作。

## 接口总览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/dicts` | 查询配置列表 |
| `POST` | `/api/dicts` | 新增配置 |
| `PATCH` | `/api/dicts/:id` | 编辑配置 |
| `GET` | `/api/dicts/cache/:uuid` | 查看配置缓存 |
| `POST` | `/api/dicts/cache/refresh/:uuid` | 刷新配置缓存 |
| `GET` | `/api/dicts/export` | 导出配置 Excel |
| `POST` | `/api/dicts/import/backup` | 预检待导入文件并生成全量备份 |
| `GET` | `/api/dicts/import/backup/:backupId` | 下载当前管理员生成的导入前备份 |
| `POST` | `/api/dicts/import` | 导入配置 Excel |

## Excel 导入与备份

Excel 导入必须按下面的顺序执行，不能直接调用正式导入接口：

1. 通过分片上传接口上传 Excel，业务类型固定为 `sys-config-excel-import`。
2. 调用 `POST /api/dicts/import/backup`，提交 `uploadId`。后端先校验 Excel 表头、字段格式和重复 UUID，再从主库一致性快照生成全量备份。
3. 调用 `GET /api/dicts/import/backup/:backupId` 下载备份。前端确认下载响应有效，并要求操作员确认本地文件可用。
4. 调用 `POST /api/dicts/import`，同时提交原 `uploadId` 和 `backupId`。

生成备份请求：

```json
{
  "uploadId": "01J..."
}
```

生成成功响应的 `data`：

```json
{
  "backupId": "c1bc972b-...",
  "fileName": "sys_config_backup_20260726153000.xlsx",
  "expiresAt": "2026-08-25T15:30:00+08:00"
}
```

正式导入请求：

```json
{
  "uploadId": "01J...",
  "backupId": "c1bc972b-..."
}
```

备份对象使用私有存储，服务器保留 30 天，到期由维护任务删除。备份状态绑定当前管理员和上传会话；正式导入前还会校验备份已完整下载、未消费、未过期、上传文件摘要未变化，并比较当前主库数据与备份时快照。任一条件不满足都不会写数据库。

单次导入和备份最多处理 5000 行，数据库按主键游标每批读取 200 行。同一 `backupId` 只能成功执行一次导入。备份使用主库 `REPEATABLE READ` 一致性快照；新增、编辑和导入共用字典写入锁，正式导入会在锁内重新比对当前主库快照，并在数据库事务内执行，导入失败会回滚本次数据库变更。上述三个接口复用 `system.config.import` 权限，备份准备和正式导入的请求签名覆盖 `uploadId`、`backupId`，下载请求在 query 中携带同一 `backupId` 参与签名。

上传会话或备份状态不存在、配置类型冲突或上级配置不合法时返回参数错误，上传会话归属不匹配时返回 403；字典写入锁已被占用时返回 `ServiceBusy`（HTTP 503），Redis 读取、占用或释放失败返回 `RedisUnavailable`（HTTP 503），备份清理任务不可用返回 `TaskQueueUnavailable`（HTTP 503），对象存储或本地文件故障返回内部错误。数据库提交或回滚结果无法确认时，后端保留该 `backupId` 的消费标记并删除本次已触达配置的缓存，禁止使用原备份重试；需要先核对数据库实际状态，再重新上传文件并生成备份。

备份 Excel 可重新导入以恢复备份内已有 UUID 的业务字段；普通导入不会自动删除错误导入后新增的 UUID，遇到此类恢复需求需要根据备份差异执行数据清理。

## 配置保存请求

```json
{
  "uuid": "adminMFACheckEnable",
  "title": "后台MFA强校验开关",
  "type": 6,
  "value": true,
  "example": true,
  "remark": "true 表示登录和敏感场景都强制进入 MFA 规则",
  "page": "security",
  "pid": 6
}
```

**配置类型说明**：
- `0` 分组
- `1` 对象
- `2` 数组
- `3` 字符串
- `4` 整数
- `5` 浮点数
- `6` 布尔

## 当前安全相关配置项

### IP 相关字典

| 字典标识 | 类型 | 示例值 | 说明 |
| --- | --- | --- | --- |
| `adminIpWhitelist` | `2` 数组 | `["8.8.8.8","127.0.0.1"]` | 后台 IP 白名单；数组元素为精确 IP 字符串，不支持 CIDR 或通配符；专用编辑页 `/system/config/admin-ip-whitelist` |
| `adminIpWhitelistEnabled` | `6` 布尔 | `0` | 后台 IP 白名单开关；启用后每次登录和已登录请求都校验，白名单为空时拒绝访问 |

> 已存在环境如 `sys_config.page` 为空，可手动补齐专用编辑页路径；执行后刷新配置缓存即可在列表直接跳转。
>
> ```sql
> UPDATE `sys_config` SET `page` = '/system/config/admin-ip-whitelist' WHERE `uuid` = 'adminIpWhitelist' AND (`page` = '' OR `page` IS NULL);
> UPDATE `sys_config` SET `page` = '/system/config/admin-disable-mfa-check-scenario' WHERE `uuid` = 'adminDisableMFACheckScenario' AND (`page` = '' OR `page` IS NULL);
> ```

### MFA 相关字典

| 字典标识 | 类型 | 示例值 | 说明 |
| --- | --- | --- | --- |
| `adminMFACheckEnable` | `6` 布尔 | `true` | 后台系统强制开启 MFA 校验开关；开启后，登录校验和后台代操作敏感场景都会进入 MFA 规则 |
| `adminMFACheckFrequency` | `4` 整数 | `300` | MFA 二次校验频率，单位秒；在频率窗口内可复用最近一次场景票据，前端同一标签页会按票据过期时间自动复用，超时后需要重新校验 |
| `adminDisableMFACheckScenario` | `1` 对象 | `{"13":"前台用户管理","14":"API运行态热加载"}` | 禁用 MFA 二次校验的场景集合；对象 key 为场景值，登录场景不受此配置影响；专用编辑页 `/system/config/admin-disable-mfa-check-scenario` |

### 场景值说明

| 场景值  | 场景常量                               | 说明           |
|------|------------------------------------|--------------|
| `0`  | `MFAScenarioLogin`                 | 登录后校验        |
| `1`  | `MFAScenarioChangePassword`        | 修改密码         |
| `2`  | `MFAScenarioStatus`                | 修改 MFA 状态    |
| `3`  | `MFAScenarioSecret`                | 修改 MFA 秘钥    |
| `4`  | `MFAScenarioUserStatus`            | 修改管理员状态      |
| `5`  | `MFAScenarioAddUser`               | 新增管理员        |
| `6`  | `MFAScenarioEditUser`              | 编辑管理员资料/角色   |
| `7`  | `MFAScenarioResetUserPassword`     | 后台重置管理员密码    |
| `8`  | `MFAScenarioResetUserInitialState` | 后台重置管理员首次状态  |
| `9`  | `MFAScenarioDeleteUser`            | 后台删除管理员      |
| `10` | `MFAScenarioUserTagLeaseRelease`   | 释放用户标签工作流互斥锁 |
| `11` | `MFAScenarioSecretKeyManage`       | 秘钥管理敏感操作     |
| `12` | `MFAScenarioRuntimeConfigManage`   | 运行配置发布/回滚/导入 |
| `13` | `MFAScenarioUserManage`         | 前台用户管理敏感操作   |
| `14` | `MFAScenarioAPIRuntimeManage`      | API 运行态热加载      |

### 规则补充

- 个人中心修改自己密码且已提供旧密码时，不额外要求 MFA 二次票据。
- 个人中心修改自己的 MFA 状态、MFA 秘钥时，必须先完成对应场景校验。
- 后台代操作是否要求 MFA，统一以 `adminMFACheckEnable` 和 `adminDisableMFACheckScenario` 为准。
- 后台重置密码、重置首次状态、删除管理员均已使用独立场景值，可单独配置禁用校验。
- 详细业务规则见 [多因素认证与管理员角色规则](角色文档/后端开发/多因素认证与管理员角色规则.md)。

## 统一响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |
| data | object/array/null | 否 |  | 配置列表、配置详情、导入结果或缓存刷新结果 |

### 配置 data 内部字段

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| id | int | 是 |  | 配置 ID |
| uuid | string | 是 |  | 配置标识 |
| title | string | 是 |  | 配置标题 |
| type | int | 是 |  | 配置类型 |
| value | any | 否 |  | 配置值 |
| page | string | 否 |  | 所属页面 |
| pid | int | 否 | 0 | 父级配置 ID |
