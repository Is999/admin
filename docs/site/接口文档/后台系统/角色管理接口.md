# 角色管理接口

---

## 1. 查询角色列表

### 请求示例

```http
GET /api/roles?page=1&pageSize=10&title=运营&status=1
```

### 查询参数

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| page | int | 否 | 1 | 页码 |
| pageSize | int | 否 | 10 | 每页数量 |
| title | string | 否 |  | 角色名称 |
| status | int | 否 |  | 状态，1 启用，0 禁用 |

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "查询成功",
  "data": {
    "list": [
      {
        "id": 2,
        "title": "运营",
        "pid": 0,
        "status": 1,
        "description": "运营角色",
        "manageable": true,
        "canCreateChild": true
      }
    ],
    "total": 1
  }
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |
| data | object | 是 |  | 角色分页数据 |

#### data 内部字段

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| list | array | 是 | [] | 角色列表 |
| total | int | 是 | 0 | 总数 |

`list[]` 中的 `manageable` 表示当前管理员是否可管理该角色，`canCreateChild` 表示是否可在该角色下新增子角色。

## 2. 查询角色树

### 请求示例

```http
GET /api/roles/tree
```

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "查询成功",
  "data": [
    {
      "id": 1,
      "title": "超级管理员",
      "pid": 0,
      "status": 1,
      "manageable": true,
      "canCreateChild": true,
      "children": []
    }
  ]
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |
| data | array | 是 | [] | 角色树 |

角色树节点的 `manageable` 表示当前管理员是否可编辑该角色，`canCreateChild` 表示当前节点及其父级路径启用且允许在其下新增子角色。前端状态、编辑、删除和新增子级入口直接使用这两个字段；超级管理员角色仍禁止禁用和删除。

## 4. 新增角色

### 请求示例

```http
POST /api/roles
Content-Type: application/json

{
  "title": "运营",
  "pid": 0,
  "status": 1,
  "description": "运营角色"
}
```

### 字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| title | string | 是 |  | 角色名称 |
| pid | int | 否 | 0 | 父级角色 ID |
| status | int | 否 | 1 | 状态，1 启用，0 禁用 |
| description | string | 否 |  | 角色说明 |

角色创建只保存基础资料。正常路由权限和文档权限统一通过 `PATCH /api/roles/permissions/:id` 配置，避免 `role.add` 越权承担角色授权能力。

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "创建成功"
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |

### 重复名称响应

```json
{
  "status": false,
  "code": 30001,
  "message": "角色[运营]已存在"
}
```

## 5. 编辑角色

### 请求示例

```http
PATCH /api/roles/2
Content-Type: application/json

{
  "title": "运营",
  "pid": 0,
  "description": "运营角色"
}
```

路由模板：`PATCH /api/roles/:id`

### 路径参数

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| id | int | 是 |  | 角色 ID |

### 字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| title | string | 是 |  | 角色名称 |
| pid | int | 是 |  | 明确的父级角色 ID；传 `0` 表示根角色，超级管理员角色固定为根角色 |
| description | string | 是 |  | 角色说明；传空字符串表示清空 |

角色编辑必须显式提交 `title`、`pid` 和 `description`，避免漏传字段被解释为清空或移动到根节点。状态只通过 `PATCH /api/roles/status/:id` 修改。换父级后，后端会在同一事务内重建全部子孙角色族谱，并按新父级授权范围收敛整棵角色子树；权限增删仍只使用专用授权接口。

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "更新成功"
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |

## 8. 查询角色权限树

> 安全边界：超级管理员角色只读展示全部启用权限；普通角色只能在其父角色已拥有的权限范围内配置。

### 请求示例

```http
GET /api/roles/permissions/tree/2
```

路由模板：`GET /api/roles/permissions/tree/:id`

### 路径参数

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| id | int | 是 |  | 角色 ID |

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "查询成功",
  "data": {
    "routePermissions": [],
    "docPermissions": [],
    "writable": true
  }
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |
| data | object | 是 |  | 两类权限数据 |
| data.routePermissions | array | 是 | [] | 正常路由权限树 |
| data.docPermissions | array | 是 | [] | 精确文档权限列表，按 `site + path` 分组展示 |
| data.writable | bool | 是 | false | 当前角色权限是否允许修改；超级角色或超出管理范围时为 `false` |

## 9. 覆盖保存角色权限

> 安全边界：超级管理员角色权限只读；只有超级管理员在父级为顶级/超级管理员时可选择全部权限，普通管理员只能配置自己角色的后代角色。正常路由权限会补齐祖先目录/菜单；文档权限按 `site + path` 精确授权，并自动补齐对应文档站入口路由。两类权限均按父角色实际授权范围裁剪。

### 请求示例

```http
PATCH /api/roles/permissions/2
Content-Type: application/json

{
  "routePermissionIds": [1, 2, 3],
  "docPermissionIds": [1, 2]
}
```

路由模板：`PATCH /api/roles/permissions/:id`

### 路径参数

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| id | int | 是 |  | 角色 ID |

### 字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| routePermissionIds | int[] | 是 | [] | 正常路由权限 ID 列表 |
| docPermissionIds | int[] | 是 | [] | 精确文档权限 ID 列表 |

两类列表都必须显式提交；空数组表示撤销对应类型的全部授权，列表元素必须为正整数。

### 响应示例

```json
{
  "status": true,
  "code": 1,
  "message": "保存成功"
}
```

### 响应字段说明

| 字段 | 类型 | 是否必须 | 默认值 | 字段解释 |
|------|------|----------|--------|----------|
| status | bool | 是 | false | 状态: true 成功, false 失败 |
| code | int | 是 | 1 | 业务状态码 |
| message | string | 否 |  | 消息 |

### 高危操作说明

- 角色名称必须唯一，新增或编辑重复名称时返回业务码 `30001`。
- 禁用角色时会级联禁用全部下级角色，并清理相关缓存；缓存同步失败时返回 `data.syncPending=true`，数据库变更已经提交，不要重复操作。
- 启用角色前要求全部上级角色已启用；新增或换父级也不能挂到禁用角色路径下。重新启用父角色不会自动启用历史子角色。
- 删除角色时会级联软删除全部下级角色，同时清理管理员角色关系、正常路由权限关系和文档权限关系。
- 角色授权变更会精确失效受影响角色的路由权限和文档权限关系缓存。
- 收到 `data.syncPending=true` 表示精确失效任务已进入自动补偿；补偿完成前鉴权返回 HTTP 503，持续异常时排查 Redis、主库和 `security_cache_sync` worker 日志，不要重复提交原变更。
